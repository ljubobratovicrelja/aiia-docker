host          : x86_64, 29.9.2 engine, 5.6.1 compose

image         : aiia-docker/inference:stage-3-gpu
compose files : compose.yaml + compose.gpu.yaml (override: build.target gpu, device reservation, offload env)
runs per path : 3
prompt        : Write a Python function that returns the nth Fibonacci number. Include only the code and one short comment.

This is the same prompt and the same request body as evidence/bench-cpu.txt:
  temperature 0, max_tokens 160, chat_template_kwargs {enable_thinking: false}
Same host, same pinned model revision and sha256 — the only differences are
the build target, the nvidia device reservation and the GPU offload settings.

Thinking-model note: the pinned Qwen3.5-2B GGUF is a reasoning model.
Both requests send {"chat_template_kwargs":{"enable_thinking":false}}
plus a max_tokens cap; without them the reply lands in reasoning_content
at thousands of tokens and the client times out.

Path notes:
  inference — reached only from inside the compose network via
              'docker compose -f compose.yaml -f compose.gpu.yaml exec -T
              inference curl'; inference has no 'ports:' mapping, on the
              GPU override either.  Probe pins temperature 0 and
              max_tokens 160, so runs are deterministic and token counts
              comparable across runs and across the two hosts.
  gui       — the published gradio HTTP API, unchanged by this stage.
              gui/app.py samples at its own temperature 0.7 / max_tokens
              512, so run lengths differ; effective tokens/s is the
              comparable metric.  gui tokens are counted by posting the
              returned text to llama-server's own /tokenize.

Executions: 2 consecutive executions of 3 runs per path.
The GPU is deterministic WITHIN an execution but not across them: the same
request at temperature 0 has been observed to emit one completion-token
count on every run of one execution and a different one on every run of
the next, so the completion-token count is treated as part of the
measurement (quoted next to every number) rather than as a constant
divided into elapsed time.  The stable quantity is effective tokens/s.
Every execution is kept in this artifact so the spread is visible instead
of averaged away.

Comparison against evidence/bench-cpu.txt is appended below by
scripts/bench_compare.py, once per execution and once pooled.
