======================================================================
0. What 'device memory used' means on this machine (read this before the numbers)
======================================================================
IMPORTANT: mint's 3090 Ti also drives the desktop.  Xorg, gnome-shell and the
browser compositors hold ~4.7 GiB of the 24 GiB on their own (see the process
table in section 1), so the device-wide 'Memory-Usage' counter is NOT the
model's footprint.  Two numbers are given for that reason:
  * llama.cpp's own accounting — model buffers + KV + recurrent state + compute
    (section 5: 1211.05 + 48.00 + 77.06 + 56.02 MiB, projected 1392 MiB);
  * the driver's per-process figure for /app/llama-server (1696-1698 MiB across two
    loads), which is
    the buffers plus the CUDA context.
The device counter is quoted alongside them so the arithmetic is checkable, but
it is never quoted as 'the model uses 6.4 GB'.

== 2c. what the numbers above mean ==
Device memory does NOT grow during generation: llama.cpp allocates the model
buffers, the KV cache for n_ctx=4096 and the compute buffer at load time and
then reuses them, so 'during' and 'after' are the same ~6.4-6.5 GiB device-wide
figure and the model's own share stays 1696-1698 MiB.  What changes under load is
utilization (6-8% idle vs 94% generating), not memory.  The GB10 artifact had
the same shape for a different reason (unified memory, no VRAM counters); here
the counters exist and still show no per-request growth.
