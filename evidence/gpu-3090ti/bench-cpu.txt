Thinking-model note: the pinned Qwen3.5-2B GGUF is a reasoning model.
Both requests send {"chat_template_kwargs":{"enable_thinking":false}}
plus a max_tokens cap; without them the reply lands in reasoning_content
at thousands of tokens and the client times out.

Path notes:
  inference — reached only from inside the compose network via
              'docker compose exec -T inference curl'; inference has no
              'ports:' mapping at all.  Probe pins temperature 0 and
              max_tokens 160, so runs are deterministic and token counts
              comparable across runs.
  gui       — the published gradio HTTP API.  gui/app.py samples at its
              own temperature 0.7 / max_tokens 512, so run lengths differ
              slightly from the isolated path; that is precisely why the
              comparable metric is effective tokens/s, not raw elapsed.
  gui tokens are counted by posting the returned text to llama-server's
  own /tokenize, which was verified to equal usage.completion_tokens
  exactly on the isolated path (gradio's stream carries no usage block).
